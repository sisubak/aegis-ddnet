# score audit (in progress)


## scoreworker.cpp (2028 строк) — обзор

Общий вывод: во всех SQL-запросах клиентские данные (имена игроков, карта, код сейва, сервер) передаются
через параметры `?` + BindString/BindInt/BindBlob. В `str_format` подставляются только серверно-контролируемые
значения: `GetPrefix()`, `CollateNocase()`, `Random()`, `InsertIgnore()`, `False()`, `InsertTimestampAsUtc()`,
и целочисленные `LimitStart`/константы. SQL-инъекций через клиентские строки НЕ обнаружено. Ниже — точечные заметки.

### scoreworker.cpp:1238 (ShowTeamTop5)
Проблема: `LIMIT %d, ?` — `LimitStart` подставляется через `%d` прямо в строку запроса, а не биндится.
Значение вычисляется как `std::max(absolute(pData->m_Offset) - 1, 0)` — это int от клиента (offset команды),
но диапазон ограничен и это число, инъекция невозможна (только int). Замечание: стилистически лучше биндить,
но уязвимости нет.
Фикс: не требуется по безопасности; для единообразия можно вынести LimitStart в BindInt.

### scoreworker.cpp:1327,1331 (ShowPlayerTeamTop5)
Проблема: аналогично `LIMIT %d, 5` — `LimitStart` через `%d`. Только int, инъекции нет.
Фикс: не требуется по безопасности.

### scoreworker.cpp:107-133 (CTeamrank::FormatNames)
Проблема: потенциальная логическая тонкость — `NamesSize = BufSize - str_length(aMore)`. Если BufSize мал,
NamesSize может стать отрицательным, тогда `str_append(pBuf, aName, NamesSize)` вызывается с отрицательным лимитом.
str_append в ddnet clamp'ит размер, переполнения буфера нет (str_* безопасны). Реальной уязвимости нет.
Фикс: не требуется; str_* функции DDNet ограничивают запись размером буфера.

### scoreworker.cpp:143-181 (GetSqlTop5Team)
Проблема: `TeamSize = pSqlServer->GetInt(4)` берётся из БД и используется как счётчик цикла Step().
Значение из доверенной БД, не напрямую от клиента. Ограничено вставкой в m_aaNames проверкой `< MAX_CLIENTS`.
Переполнения нет.
Фикс: не требуется.

### scoreworker.cpp:886-887,1166-1167,1273-1274 (aServerLike[16])
Проблема: `str_format(aServerLike, sizeof(aServerLike), "%%%s%%", pData->m_aServer)` — буфер всего 16 байт,
имя сервера обрезается. Значение потом биндится через BindString (не инъекция). str_format безопасно обрезает.
Фикс: не требуется по безопасности; при длинном m_aServer будет обрезка (функциональная мелочь).

### scoreworker.cpp:1768 aBuf[65536] / 1892 aSaveString[MAX_SAVE_STRING_LENGTH]
Проблема: SaveTeam/LoadTeam оперируют большими буферами savegame. Запись идёт через BindString и
GetString(sizeof(...)) — переполнения нет. FromString парсит и возвращает код ошибки (проверяется Num != 0).
Фикс: не требуется.

### scoreworker.cpp:1978-1983 (GetSaves, EscapeLike)
Проблема: имя игрока экранируется через sqlstr::EscapeLike перед вставкой в LIKE-паттерн и биндится.
Корректная защита от LIKE-инъекции. ОК.
Фикс: не требуется.

Общая заметка по исключениям: функции возвращают bool и не бросают исключений; dynamic_cast может вернуть
nullptr при несовпадении типа, но здесь тип гарантирован вызывающей стороной. pResult не проверяется на nullptr
после dynamic_cast (напр. строки 216, 297, 347) — теоретически при рассинхроне типа запроса будет разыменование
nullptr (краш, не эксплойт). Низкий риск.
