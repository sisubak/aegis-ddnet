# Fix: issue #12596 — "Vote code has most-of-the-time-dead Veto condition"

Файл: `src/game/server/gamecontext.cpp`, функция `CGameContext::OnTick()`, блок `// update voting` (около строк 1284–1456).

## Суть бага

Логика голосования пересчитывает голоса и флаги вето (`m_Veto`, `m_VetoStop`)
только внутри блока `if(m_VoteUpdate)` (строка ~1293). Внутри этого блока сначала
делается `m_Veto = false; m_VetoStop = false;`, а затем при проходе по игрокам они
могут выставиться в `true` по time-based условиям (игрок долго на сервере / не afk).

`m_VoteUpdate` выставляется в `true` только когда кто-то реально меняет свой голос
(в обработчике голосования). Момент закрытия голосования (`time_get() > m_VoteCloseTime`)
приходит по таймеру, а не по изменению голоса, поэтому на закрывающем тике
`m_VoteUpdate` почти всегда `false`. В результате блок пересчёта не выполняется,
и условия, использующие `m_Veto`:

- строка ~1412: `m_VoteEnforce = (m_VoteWillPass && !m_Veto) ? VOTE_ENFORCE_YES : VOTE_ENFORCE_NO;`
- строка ~1446: `if(m_VetoStop || (m_VoteWillPass && m_Veto))`

работают со значением `m_Veto`, которое было посчитано в какой-то прошлый тик
(последнее изменение голоса) либо вообще осталось `false` с инициализации. Т.е.
условие вето «почти всегда мёртвое» — оно срабатывает корректно лишь в редком
случае, когда последнее изменение голоса случайно совпало с закрывающим тиком.

## Что изменено (минимальный безопасный фикс)

Перед проверкой `if(m_VoteUpdate)` добавлен принудительный пересчёт при закрытии
голосования: если `time_get() > m_VoteCloseTime`, форсируем `m_VoteUpdate = true`,
чтобы `m_Veto`/`m_VetoStop` были заново посчитаны на закрывающем тике с актуальными
time-based условиями.

old:
```cpp
		else
		{
			int Total = 0, Yes = 0, No = 0;
			if(m_VoteUpdate)
```

new:
```cpp
		else
		{
			// Force a vote recount when the vote is about to close, so that
			// m_Veto/m_VetoStop are (re)computed with the current time-based
			// conditions on the closing tick, even if nobody changed their vote.
			if(time_get() > m_VoteCloseTime)
				m_VoteUpdate = true;

			int Total = 0, Yes = 0, No = 0;
			if(m_VoteUpdate)
```

## Почему это безопасно

- Не переименовывает функции, не трогает физику.
- Затрагивает только тик закрытия голосования (`time_get() > m_VoteCloseTime`) — на
  обычных тиках поведение не меняется, лишней нагрузки на каждый тик нет.
- На закрывающем тике голосование всё равно завершается (`EndVote()` в одной из
  веток enforce), поэтому форсированный пересчёт выполняется ровно один раз и не
  зацикливается. `EndVote()` обнуляет `m_VoteCloseTime`, так что повторного входа
  в блок не происходит.
- Ветка `else if(m_VoteUpdate)` (отправка статуса) в этом случае не достигается,
  т.к. при `time > closeTime` всегда срабатывает ветка YES/NO enforce.

Синтаксис изменённого фрагмента перепроверен чтением файла (строки 1284–1300 и
1405–1456) — блок корректен.
