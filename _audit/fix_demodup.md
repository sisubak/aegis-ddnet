# fix_demodup.md — Issue #11144 (Server records duplicated messages to server demos)

Автор: mister/ \day
Проект: DDNet (C++), C:\Users\WWWWWUeHaA\Desktop\antiddos

## Симптом
При записи серверного демо с 2+ клиентами broadcast-сообщение (и любое
сообщение, отправленное всем) попадает в демо один раз НА КАЖДОГО клиента,
т.е. дублируется столько раз, сколько игроков онлайн.

## Корень бага (проверено по коду)
Файл: src/engine/server.h, шаблон SendPackMsg, строки 89-124.

Когда ClientId == -1 (всем), SendPackMsg НЕ идёт по ветке "всем" в
CServer::SendMsg, а вручную циклом вызывает SendPackMsgTranslate для каждого
клиента (это нужно для 0.6/0.7 и 128-player трансляции). Каждый такой вызов
заканчивается в CServer::SendMsg с конкретным ClientId >= 0.

Файл: src/engine/server/server.cpp, SendMsg, ветка ClientId >= 0, строки 1002-1011:
    if(!(Flags & MSGFLAG_NORECORD))
    {
        if(m_aDemoRecorder[ClientId].IsRecording())        // per-client демо — ОК
            ...RecordMessage(...);
        if(m_aDemoRecorder[RECORDER_MANUAL].IsRecording()) // серверное демо
            ...RecordMessage(...);                          // <-- пишется на КАЖДОЙ итерации цикла
        if(m_aDemoRecorder[RECORDER_AUTO].IsRecording())   // серверное демо
            ...RecordMessage(...);                          // <-- пишется на КАЖДОЙ итерации цикла
    }

RECORDER_MANUAL и RECORDER_AUTO — это ОДНО общее серверное демо. Оно должно
получить сообщение, адресованное всем, ровно один раз, но получает N раз.

Для сравнения ветка ClientId < 0 в SendMsg (строки 960-966) пишет в
серверные рекордеры ровно один раз — но в эту ветку SendPackMsg с -1 не
попадает из-за необходимости пер-клиентской трансляции.

## Уверенность
Я уверен в корне бага: дублирование идёт от строк 1007-1010, вызываемых в
цикле из server.h:96-98.

## Рекомендуемый фикс (безопасный, минимальный)
Записывать в RECORDER_MANUAL/RECORDER_AUTO только когда сообщение реально
адресовано конкретному клиенту, а не является частью broadcast-цикла.

Практично: в SendPackMsg (server.h) при ClientId == -1 добавлять флаг
MSGFLAG_NORECORD к пер-клиентским вызовам в цикле (чтобы SendMsg не писал в
серверные рекордеры на каждой итерации), а per-client рекордеры
m_aDemoRecorder[i] всё равно писать. Но per-client запись сейчас тоже в том же
блоке — значит нужно разнести: строку 1005-1006 (per-client) оставить, а
1007-1010 (серверное демо) выполнять только один раз.

Чистый вариант: убрать запись в RECORDER_MANUAL/AUTO из ветки ClientId >= 0
и в SendPackMsg после broadcast-цикла один раз позвать запись в серверные
рекордеры (по аналогии с веткой ClientId < 0, repack в 0.6 формат).

Требует аккуратного тестирования записи/воспроизведения демо (0.6 и 0.7).
Риск: средний — трогает семантику записи демо. Не применяю автоматически без
прогонки теста записи/воспроизведения, которого в окружении нет.
