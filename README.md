## О проекте

Форк DDNet (версия сервера 20.2), переработанный под защиту от DDoS-атак. Основная работа вынесена в сетевой слой: паразитный трафик отсеивается и лимитируется на входе, до того как запросы доходят до игровой логики. Проект находится в стадии альфа-тестирования, часть функций ещё обкатывается.

## Возможности

- Фильтрация входящего трафика на сетевом уровне
- Ограничение частоты запросов (rate-limit)
- Баны и блокировки на сетевом уровне
- Captcha-сервер (gate) — отсеивает ботов до входа на игровой сервер
- Защита econ от перебора пароля (бан по IP при исчерпании попыток)
- Фильтр HTTP-запросов против SSRF (блок приватных и loopback-диапазонов)
- Проверка версии через GitHub с предупреждением rcon-админам о новом релизе

## Captcha-сервер

Отдельный gate-сервер, через который проходят все новые игроки перед попаданием на игровой сервер.

Как работает:

- Сессии капчи ведутся отдельно для каждого клиента. Одновременно решать капчу могут до `sv_captcha_srv_concurrent` игроков (не по одному за раз). Очередь — только ограничитель переполнения: её длина лимитирована `sv_captcha_srv_queue_max`, и при заполнении новый игрок получает кик с сообщением, а не висит в бесконечном ожидании.
- У каждого игрока свой таймер на ответ (`sv_captcha_srv_answer_sec`), по истечении — кик.
- Игроку показывается лазерная коробка с цифровым кодом, ответ вводится в чат. Внутри коробки нулевая гравитация и программная коллизия по границам — выйти за пределы капчи нельзя.
- Анти-брутфорс по IP: больше `sv_captcha_srv_max_fails` неверных или просроченных попыток за окно `sv_captcha_srv_fail_window_sec` секунд приводят к временному кулдаун-кику с этого IP.
- При верном ответе игрок редиректится на игровой порт, его адрес добавляется в вайтлист, общий между gate и игровым сервером.
- Лобби-карта генерируется процедурно, отдельный файл-заготовка не нужен.

Вайтлист — текстовый файл формата `ip unix_timestamp` (путь `sv_captcha_srv_ipc_path`, по умолчанию `captcha_whitelist.txt`). Записи старше `sv_captcha_srv_whitelist_ttl_sec` секунд (по умолчанию 3600, 0 = бессрочно) отбрасываются при чтении. Размер ограничен `sv_captcha_srv_whitelist_max` записями, при переполнении вытесняются самые старые. Файл перечитывается по изменению mtime.

Передача подтверждённых IP от gate к игровому серверу идёт по loopback UDP (порт `sv_captcha_srv_ipc_port`). Пакет аутентифицируется HMAC-SHA256 от общего секрета над значением nonce+ip, а не передачей секрета открытым текстом; есть защита от повторов по nonce и ограничение частоты приёма. Если `sv_captcha_srv_ipc_secret` пустой, сервер в captcha-режиме отказывается стартовать. Ограничение: этот IPC работает только в пределах одной машины.

Клиент, подключившийся напрямую на игровой порт без вайтлиста, получает кик с понятным сообщением (нужно идти через gate-порт), а не висит в бесконечном connecting.

| Конфиг | По умолчанию | Описание |

## Аварийная миграция портов (экспериментально)

Экспериментальный механизм (`sv_anus_sob_*`): при детекте флуда сервер может мигрировать на случайный «аварийный» порт, форкнув новый процесс. Функция помечена как EXPERIMENTAL, не для продакшена, по умолчанию выключена и работает только на Unix.

Трезвый вердикт: от волюметрического UDP-флуда прыжок по порту из userspace не спасает — пакеты всё равно доходят до сетевой карты и забивают канал/pps раньше, чем приложение что-либо решает. Механизм имеет смысл разве что против узко-таргетированных по порту сценариев, но не против объёмной атаки.

Детали и ограничения:

- Мигрированный чайлд отключает регистрацию в мастер-листе — иначе «секретный» аварийный порт тут же снова станет публичным.
- Запуск миграции сейчас происходит из игрового тика (известное ограничение).
- Состояние игроков сохраняется в `/tmp` с правами 0600 и чистится при старте и выходе.
- Детектор срабатывает по `sv_anus_sob_threshold` пакетам за окно `sv_anus_sob_window_ms` и требует минимум `sv_anus_sob_min_unique_sources` различных источников, чтобы не реагировать на единичный шумный адрес.

### Конфиги аварийной миграции

| Конфиг | По умолчанию | Описание |
| --- | --- | --- |
| `sv_anus_sob_mode` | 0 | Включить аварийную миграцию портов (EXPERIMENTAL, не для продакшена) |
| `sv_anus_sob_threshold` | 4000 | Пакетов за окно, запускающих миграцию |
| `sv_anus_sob_window_ms` | 1000 | Длина скользящего окна детектора в мс |
| `sv_anus_sob_port_min` | 20000 | Нижняя граница случайного аварийного порта |
| `sv_anus_sob_port_max` | 60000 | Верхняя граница случайного аварийного порта |
| `sv_anus_sob_emergency_bin` | `./DDNet-Server` | Путь к бинарю аварийного сервера (цель fork+exec) |
| `sv_anus_sob_ipc_path` | `anus_sob.sock` | Локальная точка IPC (UDS на Linux, именованный канал на Windows) |
| `sv_anus_sob_grace_ms` | 3000 | Сколько мс родитель живёт после редиректа клиентов перед выходом |
| `sv_anus_sob_child_wait_ms` | 2000 | Сколько мс родитель ждёт готовности мигрированного чайлда перед редиректом |
| `sv_anus_sob_min_unique_sources` | 32 | Минимум различных источников в окне, чтобы считать трафик реальным DDoS |

## Проверка версии

Сервер периодически (при старте и раз в час) обращается к GitHub за списком тегов релизов. Если доступна более новая версия, чем указанная в `sv_version_current`, всем залогиненным в rcon администраторам показывается бродкаст с предупреждением, пока они не разлогинятся или не выйдут.

Конфиг:

- `sv_version_check` — включить/выключить проверку (по умолчанию 1)
- `sv_version_check_url` — URL с тегами релизов (по умолчанию репозиторий проекта)
- `sv_version_current` — тег текущей сборки для сравнения

## В разработке / сырое

- Визуал капчи простой: цифры из лазерных сегментов, без искажений против OCR-ботов
- IPC между gate и игровым сервером (файл-вайтлист + loopback UDP) работает только в пределах одной машины, для разнесённых серверов пока не годится
- Аварийная миграция портов (`sv_anus_sob_*`) — экспериментальная, не для продакшена, от волюметрического флуда не защищает
- Часть параметров (размер коробки, часть таймингов) зашита в код и требует пересборки для подстройки; число цифр настраивается через `sv_captcha_srv_digits`
- Юнит-тесты покрывают логику капча-сессии, вайтлиста и очереди (`src/test/captcha_test.cpp`), а также state-кодек миграции (`src/test/anus_sob_test.cpp`); интеграционная и визуальная проверка пока ручная

## Статус

Проект находится в стадии альфа-тестирования (текущий релиз v5, база DDNet 20.2). Часть конфигов временные и могут быть неполными, поведение сервера может меняться без предупреждения.
