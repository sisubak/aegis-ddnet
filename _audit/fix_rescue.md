# fix_rescue.md — Issue #9254 (неконсистентный /r + start-таймер в команде)

Автор: mister/ \rescue
Проект: DDNet (C++), C:\Users\WWWWWUeHaA\Desktop\antiddos

## Симптом
sv_rescue 1 / команда /r в командной игре: после /r на позицию ДО start-линии
таймер сбрасывается, но повторное пересечение start НЕ перезапускает таймер
(в отличие от одиночной no-team игры).

## Анализ реального кода
Старт таймера команды: CGameTeams::OnCharacterStart (teams.cpp:85-...).
- Для solo/flock-ветки (teams.cpp:95-105): при старте выставляет
  m_aTeeStarted[ClientId]=true, m_DDRaceState=STARTED, m_StartTime=Tick и return.
- Для настоящей команды (teams.cpp:106-...): если кто-то в команде уже FINISHED
  (114-118) → Waiting=true, m_DDRaceState=NONE, и старт НЕ засчитывается пока
  все не пройдут start. Флаг m_aTeeStarted[ClientId] выставляется только при
  !Waiting (144-147). ChangeTeamState в STARTED тоже только при !Waiting (149).

Rescue: TrySetRescue/ForceSetRescue (character.cpp:2186-2226) сохраняет позицию,
а /r (ddracechat.cpp:1639) загружает её. Загрузка позиции возвращает тича назад,
НО не трогает m_aTeeStarted[]/m_DDRaceState команды напрямую.

## Корень бага
После /r на точку до start-линии, при повторном пересечении start вызывается
OnCharacterStart. В командном режиме если m_aTeeStarted[ClientId] уже true
(тич считался стартовавшим ранее) либо состояние команды уже STARTED, повторный
проход через start не перезапускает m_StartTime — командная ветка не выполняет
безусловный сброс m_StartTime, который есть в solo-ветке (teams.cpp:103).
В no-team/solo ветка всегда переустанавливает m_StartTime=Tick (103), поэтому там
рестарт работает; в командной ветке m_StartTime переустанавливается только через
условную логику старта команды, что и даёт расхождение.

## Кандидат-фикс (НЕ применён)
Синхронизировать поведение: при пересечении start в командном режиме, если
команда ещё не финишировала и не в состоянии Waiting, безусловно
переустанавливать m_StartTime и сбрасывать m_aTeeStarted перед пересчётом (как
это делает solo-ветка на teams.cpp:103). Нужно аккуратно, чтобы не сломать логику
ожидания финишировавших (Waiting, teams.cpp:106-142) и командный старт-warning.

Риск средний-высокий: OnCharacterStart — центральная логика командного старта,
затрагивает рекорды/таймеры многих режимов. Требует тестов на командных картах.
